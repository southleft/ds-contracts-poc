## 3. THE TWO THINGS THAT NEED THE OWNER

Everything else that could be done without a decision has been done. These
cannot: picking either without a reviewed source fact is the invented
FILL/FIXED teaching the standing constraints forbid.

### Gate 1 — does a table root hug or fill?

`recipe/fixtures/table.ts:102-105` declares `resize.root/row/cell` all
`hug-contents`. The live probe widens an instance by 64px and requires that
width to stick — fill semantics. One of the two is wrong.

**Measured since:** the captured MUI Table root computes to `width: 688px` and
**every row computes to 688px**. The fixture's `hug-contents` is not a source
fact and the captured truth contradicts it. Changing it is still an authoring
change, but it is no longer a coin flip.

### Gate 2 — does `table@1` get a column width model?

**This is an unreceipted silent loss, which raises its severity.** The captured
MUI Table renders 5 columns × 3 rows with each column at exactly ONE width
(48 / 208.125 / 100.969 / 110.484 / 88.4219, each appearing 3×). The source's
columns ARE aligned — `table-layout: auto` aligns them. Our Figma mint gives the
same column 127px in one row and 159px in another. **The mint loses a property
the source has, and carries no receipt for it.** docs/32's bar is "named or
carried; zero silent losses".

Two grounded options, neither chosen here:

- **Lower it** — compute one width per column from the rendered source and emit
  explicit per-column widths. Inputs measured, not invented.
- **Receipt it** — declare `table-layout: auto` a `no-figma-primitive` loss and
  accept ragged mints wherever content exceeds a declared minimum.

Evidence: `recipe/evidence/table-column-model-source-facts.json`,
`recipe/evidence/table-column-alignment-v27.json`.
Decision page: https://claude.ai/code/artifact/3c61fea8-a682-447e-a1df-8d89634f0508

## 4. The instrument that changed the Table climb

`recipe/table-tail-census.ts` replays a persisted extract
(`private/table-live-vNN-transaction/004-extract.raw.json`) through the current
host-normalize **with zero Figma writes**, and reports every remaining
difference instead of the first. It took the tail from "unknown depth, one gap
per live cycle" to six measured classes and closed them.

**Use it before spending a live cycle.** Two hard-won caveats:

1. **A substrate is only valid for the WRITER that produced it.** A writer change
   invalidates it; only a fresh live run restores it.
2. **It measures BOTH extract comparisons now.** It originally measured only the
   fixed-point IR diff and reported "0" while the live run still refused at
   independent root accounting. It now runs `compareSceneToExpectedPlan` too.

The census's stated limit — extract-side only, writer-side defects surface only
live — is exactly the class that then bit at v25. Stating a limit you cannot
close is still worth it: it turned a surprise into a confirmation.

## 6. Calendar, precisely

`calendar@1` is green at 21 tests: 10 components in three sets
(`calendar/set` 4, `calendar/week-set` 2, `calendar/day-set` 4), fixed point
stable, refuses an unsupported structural edit, a short week, and a hugged day
cell. `recipe/calendar-figma-writer.ts` exists and is hermetic.

Two things it got right the hard way:

- **A week cannot be an instance.** The grid first held week instances carrying
  only a week number, so a three-week month rendered the same seven days three
  times. It compiled and held its fixed point and was not a calendar. Day state
  varies WITHIN a week; an instance picks one variant for the whole component.
  The grid owns day instances.
- **The Date-in-grammar problem is solved by carrying the RENDERED month** as
  content, not a `Date` to re-render from. No `$date` marker invented.

**Two standing refusals** (`recipe/evidence/calendar-named-refusal-v1.json`):
no live mint, and **single-library**. `react-day-picker@10.0.1` is held BLIND by
`examples/day-picker/PROVENANCE.md` so it can serve as the unseen-library exam —
**do not author an adapter for it casually**. The eventz `date-picker.contract.json`
is an empty shell (`props: []`, `anatomy: { root: {} }`).

## 10. A defect I introduced and fixed, worth remembering

Adding `calendar / date-picker` to `packages/schema` and `packages/core`
re-bakes the **plugin engine bundle** — core is compiled into it. The drift guard
in `scripts/build-plugin-zip.mjs` refused to package, correctly:

    a fresh bundle hashes 099261cf… (864984 bytes)
    but the committed receipt records c684ea0b… (863419 bytes)

That one stale hash cascaded into `plugin:zip`, `plugin:check`, `plugin:ui-check`,
`V1-COMPAT-04`, `V1-SEC-01`, audit rows AUD-V08 and AUD-U21, and four eval
regressions (227 → 223). Fixed in `cef8e4e9a` with
`node scripts/build-plugin-zip.mjs --update-engine-receipt`.

**Rule:** any change to `packages/core` or `packages/schema` re-bakes the plugin
engine. Re-record `figma-sync/plugin/engine.receipt.json` in the same commit.

Also: the readiness receipts and `evals/results.json` from the run that caught
this were deliberately NOT committed — they measured a broken tree. A fresh
readiness runs against the fixed commit instead. A receipt of a broken state is
worse than a stale one.
